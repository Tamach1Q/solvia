# SOLVIA O&M統合管理 デモ

統合監視・異常対応と、過去履歴＋現在データを使った点検支援を一つの業務UIに統合した操作デモです。管理側から現場へ共有URLで点検を依頼し、スマートフォンで入力・撮影した結果を管理画面と報告書へ戻せます。

## 起動

```bash
npm install
npm run dev
```

`http://127.0.0.1:5173`を開きます。

## デモシナリオ

統合監視 → 異常案件 → 遠隔再起動 → 現地判断 → 修繕・復旧、および点検予定 → 過去履歴 → 重点点検 → 現場へ依頼 → スマホ入力・カメラ撮影 → 管理側で結果確認 → 写真入り報告書 → MISORA登録（モック）の流れを操作できます。

スケジュール管理、Google Calendar連携、担当者の推薦・アサイン機能は対象外です。

## ナレッジ蓄積・共有デモ（feature/knowledge）

異常案件を軸に、ノウハウが「使われる→溜まる→次に届く」流れを見せます。

1. 統合監視 → 青森大間発電所（PCS-03停止）
2. 異常案件：「ナレッジ照合」で同型PCS×内部温度異常の事例6件がヒット。原因候補と切り分け手順に、元になった事例（K-xxx）を表示。「過去の類似事例」で事例カードのドロワーが開く
3. 遠隔再起動 → 一時復旧後に再停止 → 現地対応判定（持参品もナレッジから）
4. 「担当者のiPadへ手順を送る」：共有URLで、ナレッジ付きの切り分け手順が現場画面に届く（入力はすべて任意。未入力のまま提出できる）
5. 現場で提出すると、管理側の案件が自動で完了まで進み、現場入力＋通話記録からAIが下書きしたナレッジが「確認待ち」で自動登録される（AIはモック）
6. 統合監視の「最近溜まったナレッジ」に確認待ちとして表示 → クリックでナレッジ画面へ → 内容を確認して「承認して公開」
7. ナレッジ一覧：発電所名つきで表示。設備・事象・発電所で絞り込み・検索できる

iPadを使わない場合は、異常案件の「現地作業完了（手動）」→「復旧を確認して完了」でも同じくナレッジが確認待ちに登録されます。

リハーサル後は、ナレッジ画面の「デモをリセット」で公開したカードと案件の進行を初期状態に戻せます。

- `src/data/knowledgeData.ts`：事例カード・通話記録・抽出結果（すべて架空。メーカー名・アラームコードは伏せています）
- `src/services/knowledgeService.ts`：検索・抽出・公開の境界（現在はモック。公開したカードはブラウザのlocalStorageに保存）
- `src/Knowledge.tsx` / `src/knowledge.css`：ドロワー・ナレッジ化パネル・ナレッジ一覧

## 実APIについて

- `src/services/fusionSolarService.ts`: FusionSolar等の監視データ取得境界。現在はモックです。
- `src/services/misoraService.ts`: 報告書・CRM（画面表記）の履歴検索・報告書保存境界。現在はモックです。
- `src/services/sharedInspectionService.ts`: 管理画面と現場画面の共有境界です。Netlify Functions / Blobsを利用します。
- MISORA APIの有無、写真アクセス、書き込み可否、FusionSolarの取得粒度は仮定していません。
- `src/data/mockData.ts`内のデータはすべてデモ用です。

## 現場共有デモについて

- 管理画面の「現場に依頼」で、推測されにくいトークン付き現場URLを発行します。
- 現場画面の写真欄はスマートフォンのカメラを起動し、画像を縮小してアップロードします。
- 管理画面は5秒間隔で入力状況を更新し、提出後は撮影写真を報告書へ自動挿入します。
- 認証・権限管理はデモ範囲外です。共有URLを知っている人が閲覧できるため、本番化時にはログインと案件単位のアクセス制御が必要です。

## 点検生成の3層

1. 設備種別ごとの標準点検ルール
2. MISORAの過去履歴による重点項目追加
3. 現在データと履歴を整理したAI提案（固定モック）
